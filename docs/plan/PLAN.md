### 关键机制发现

- **投币节奏是核心难度来源**：连点 9 秒投完 20 枚只跑 6 个循环，币堆来不及压实就进入收尾，必失败；按推板周期投币才能达标。这符合规划里「让落币时机匹配推板，而非只按按钮节奏」的设计意图。
- **收尾时持有加力会停下来等玩家选择**（规划要求「加力不能被吞」）。这条规则生效，但任何自动化试玩都必须处理这个提示，否则会一直等待。第 2–6 关的机器人试玩都实际用掉了 1 次加力才走完结算。
- **台面输送必须以推板为参考系**。推板回撤时币在世界坐标里会跟着后退，这与真机一致；若按世界速度输送，币会被推板一路带回后方，永远到不了前缘。
- **返币筹码会显著拉长收尾**：第 4–6 关的返币会把收尾拉回「进行中」，加力再重置收尾窗口，所以这三关的最终分会比目标高出较多。这是设计允许的（规划写明「使用后重新计算收尾窗口」），但也意味着这三关的难度对玩家是否会用加力更敏感。

### 图鉴券与外观解锁

`node scripts/verify-game.mjs collection` → 16/16 通过。

- **图鉴券**只在关卡**首次通关**时发 1 张（重复刷分不再发），最多 6 张。结算页会显示「首次通关，获得图鉴券 ×N」。
- **外观**：4 种币纹（厚铜 / 银锭 / 青瓷 / 黑曜）+ 4 种机柜配色（原色 / 薄荷绿屏 / 琥珀街机 / 夜紫机柜），成本 0–2 张券。
- **只改渲染**：换装不动分值、投币次数、推板行程与盘面币数（已断言：换装后盘面仍 32 枚、目标仍 140）。
- **绿色是玩法保留色**。第一版把「青玉」做成玉绿色，实测发现与绿色返币筹码撞色、玩家分不清哪枚能返币，已改成偏蓝的「青瓷」。花纹筹码的奶白与返币筹码的绿色在所有外观下都锁定不变。
- 图鉴面板与结算面板都是居中浮层，打开图鉴时会压下结算面板，关闭后恢复（已断言）。

### 环境限制（影响验证方式）

- **Playwright 测试运行器有两个环境坑，都已解决**：
  1. 清理 `test-results` 会触发批量删除保护（同轮累计 >50 文件即拒绝）。产物少时正常，累积多了要先手工清一次。
  2. `playwright.config.ts` 原本写死 `reuseExistingServer: false`，本地已开着 dev server 时会直接报端口占用。已改成 `!process.env.CI`——本地复用、CI 起干净实例。

  最终 `npx playwright test` 在桌面 Chromium 与 iPhone Safari（WebKit）上 **28/28 通过**；需要 `npx playwright install chromium webkit`。
- 另外验证脚本 `scripts/verify-game.mjs` 仍然保留，它的优势是能跑长时物理试玩（单关最多 27 个推板循环、约 65 秒）与参数扫描，Playwright 的默认超时不适合这类用例。
- **Vite 构建需 `emptyOutDir: false`**，否则清空 `dist` 会被同一套保护拦下。

## v2 落地记录（2026-09-21，P0–P2 与界面骨架）

### 钉阵显示缩短（只改显示，不改物理）

22 根钉子的网格长度 0.30 → **0.10 米（1/3）**，**碰撞体保持 0.30 米全长**。缩短对钉子中心对称，所以屏幕位置与币的命中点都不动。

- 可见段 z ∈ [−0.77, −0.67]，恰好等于落币的 z 抖动范围（`TABLE.drop.jitterZ = 0.05`）——币永远落在看得见的那一段上。
- 常量下限：`PEG_VISUAL_HALF_LENGTH` 不得小于 `drop.jitterZ`，再短就会出现「撞到一根看不见的钉子」。
- 验收 ⓪：钉子 22 根、网格半长 0.05 米、碰撞体半长 0.15 米（`probeColliders` 补了圆柱 `halfHeight` 的读取）。

### 界面骨架

### reduced-motion 统一

以前是两套割裂实现：CSS 的 `@media (prefers-reduced-motion: reduce)` 与 `Game.reducedMotion`，互不联动；而且 `Game.reducedMotion` 还会**跳过 `fixedUpdate`**——那是改物理（推板推进与台面输送都停），不只是降动效。

现在新增 `src/systems/MotionPrefs.ts`：系统媒体查询是默认值、测试钩子可覆盖，结果写到 `<html data-motion>`，CSS 与 JS 读同一个信号；**降级只关表现**。验收 ⑰ 两条：信号一致 + 降动效后推板照常推进（循环 0→1）。

**实现中发现的一个设计耦合**：「收尾时持有加力必须提示使用或放弃」这条规则会把破产弹窗永远挡住——而设计里 Tier 2 的嘲讽文案恰恰写着「揣着没用的加力破产」。所以无尽模式在破产路径上**跳过加力提示**，让那个处境真的能发生。

### 热区为什么只在无尽模式开启

热区（得分线上移动的亮条，亮条内越线得分翻倍）给「投币时机」加了**空间维度**，但它默认只在无尽模式生效：

- 战役六关的目标分是在**没有热区**的前提下实测出来的，直接开启会让六个目标分全部失真、必须重测一轮；
- 设计文档本身把热区标为「可选轻量玩法，先不做，等 A/B/C 落地后看时机决策是否还需要加深度」；
- 机关 A~D 已经给了时机与空间两个维度的决策，所以热区作为**无尽模式的方差放大器**落地最合适（那里没有目标分，不需要重配平衡）。

`LevelConfig.hotZone` 是逐关开关，要开就得先重测那一关的目标分——这是有意的取舍，不是遗漏。
